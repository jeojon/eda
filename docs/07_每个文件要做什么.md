# 每个文件要做什么

这份文档按项目目录逐个解释文件职责。读完之后，应该能回答三个问题：

1. 这个文件属于界面、接口、数据还是实现？
2. 这个文件由谁调用，或者它调用谁？
3. 实验一需要在这个文件里写什么，不应该写什么？

## 1. 先看目录

项目目录可以分成五层：

```text
实验一_课程骨架/
├─ include/eda/         公共数据类型和接口
├─ src/gui/             wxWidgets 界面，基本已经完成
├─ src/todo/            学生要补全的四个实现文件
├─ footprints/          运行时生成的封装库目录
├─ tests/               测试目录
├─ docs/                架构和实现文档
├─ CMakeLists.txt       构建入口
├─ CMakePresets.json    Visual Studio/CMake 预设
├─ build_msvc.ps1       MSVC + Ninja 构建脚本
└─ build-msvc/          自动生成的构建目录，不要手工修改
```

最重要的分界线是：

```text
include/eda/  定义“能做什么”
src/gui/      负责“怎么点、怎么显示”
src/todo/     负责“底层具体怎么做”
```

## 2. include/eda：公共数据和接口

### `include/eda/FootprintTypes.h`

这是整个实验的数据词典，不包含文件读写、鼠标处理或 wxWidgets 代码。

里面定义了：

| 类型 | 作用 |
|---|---|
| `PadKind` | SMD 还是通孔 |
| `PadShape` | 矩形、圆角矩形、圆形 |
| `PadItem` | 一个焊盘或引脚的完整属性 |
| `SilkLine` | 一段丝印线 |
| `SilkRect` | 一个丝印矩形 |
| `SilkArc` | 一段丝印圆弧 |
| `SilkPolygon` | 多边形丝印轮廓 |
| `SilkText` | 一段丝印文本 |
| `Bounds` | 外接矩形 |
| `Footprint` | 一个封装原型 |
| `ItemType` | 选中对象类型 |
| `HitResult` | 命中测试结果，记录类型和索引 |
| `LibraryEntry` | 元件库列表中的一条记录 |

`Footprint` 是实验一的核心：

```text
Footprint
├─ 名称、分类、描述、丝印颜色、参考原点
├─ pads
├─ lines
├─ rects
├─ arcs
├─ polygons
└─ texts
```

这个文件应该保持“纯数据”。不要把查找编号、打开文件、计算命中或修改控件的代码放进来。

注意：

- 几何坐标单位统一用毫米。
- 名称、描述、文本使用 UTF-8 的 `std::string`。
- `pads`、`lines` 等使用 `std::vector`，数组下标就是对应对象的索引。
- `PadItem` 同时支持 SMD 和 THT，不要为两种焊盘再复制一套完全不同结构。

### `include/eda/IFootprintEditor.h`

定义“如何修改一个封装”的接口，位于 [IFootprintEditor.h](<E:/hp/Documents/文档(main)/OneDrive/桌面/eda/实验一_课程骨架/include/eda/IFootprintEditor.h:11>)。

接口方法：

| 方法 | 责任 |
|---|---|
| `AddSmdPad` | 添加一个 SMD 焊盘 |
| `AddThroughHolePin` | 添加一个 THT 引脚 |
| `AddLine` | 添加丝印线 |
| `AddRect` | 添加丝印矩形 |
| `AddArc` | 添加丝印圆弧 |
| `AddPolygon` | 添加丝印多边形 |
| `AddText` | 添加丝印文本 |
| `UpdatePad` | 用新属性替换一个已有焊盘 |
| `MovePad` | 只平移一个已有焊盘 |
| `RemoveItem` | 删除指定类型的指定对象 |

它只修改传进来的 `Footprint&`，不处理：

- 鼠标坐标转换；
- 画布刷新；
- 文件保存；
- 错误弹窗。

具体实现在：

```text
src/todo/FootprintEditorService.cpp
```

### `include/eda/IGeometryService.h`

定义“如何计算几何关系”的接口，位于 [IGeometryService.h](<E:/hp/Documents/文档(main)/OneDrive/桌面/eda/实验一_课程骨架/include/eda/IGeometryService.h:10>)。

接口方法：

| 方法 | 责任 |
|---|---|
| `ComputeBounds` | 计算整个封装的边界框 |
| `HitTest` | 判断模型坐标点中了哪个图元 |
| `SnapToGrid` | 将一个坐标吸附到网格 |

它只做数学计算，不创建对象，也不写文件。

典型调用：

```text
画布需要自动缩放
-> ComputeBounds

用户点击画布
-> HitTest

用户放置焊盘
-> SnapToGrid
```

具体实现在：

```text
src/todo/GeometryService.cpp
```

### `include/eda/IFootprintCodec.h`

定义“封装对象如何变成文本、文本如何变回对象”的接口，位于 [IFootprintCodec.h](<E:/hp/Documents/文档(main)/OneDrive/桌面/eda/实验一_课程骨架/include/eda/IFootprintCodec.h:11>)。

接口方法：

| 方法 | 责任 |
|---|---|
| `Serialize` | `Footprint` -> 文本 |
| `Deserialize` | 文本 -> `Footprint` |

它不负责打开文件和选择路径。它只接收一个字符串，返回一个字符串，或者把错误写入 `error` 参数。

具体实现在：

```text
src/todo/FootprintCodec.cpp
```

### `include/eda/IFootprintLibrary.h`

定义“文件系统元件库”的接口，位于 [IFootprintLibrary.h](<E:/hp/Documents/文档(main)/OneDrive/桌面/eda/实验一_课程骨架/include/eda/IFootprintLibrary.h:12>)。

接口方法：

| 方法 | 责任 |
|---|---|
| `DefaultDirectory` | 返回封装库根目录 |
| `Reload` | 重新扫描 `*.fp` 文件 |
| `Entries` | 返回扫描后的封装条目 |
| `Read` | 从文件读取一个封装 |
| `Write` | 把一个封装写入文件 |
| `Delete` | 删除一个封装文件 |

它负责文件路径、扫描、打开和保存，但文件内容的格式由 `IFootprintCodec` 负责。

具体实现在：

```text

```

声明四个创建函数，位于 [ServiceFactory.h](<E:/hp/Documents/文档(main)/OneDrive/桌面/eda/实验一_课程骨架/include/eda/ServiceFactory.h:13>)。

## 3. src/gui：已经完成的界面层

这一层负责“显示和交互”。除非发现控件问题或接口调用错误，否则不需要为了完成四个 TODO 而重写这部分。

### `src/gui/App.cpp`

程序入口。

职责：

```text
创建 wxWidgets App
-> 创建 MainFrame
-> 显示主窗口
```

这里不写封装编辑、几何计算或文件格式。

### `src/gui/MainFrame.h`

主窗口类的声明。

负责声明：

- 菜单和布局构建函数；
- 新建、打开、保存、刷新、缩放等事件；
- 当前 `Footprint`；
- 当前文件路径；
- 四个接口服务指针；
- 左右面板和属性输入控件指针。

`MainFrame` 是界面层的协调者，但它不应该自己解析 `.fp` 文件。

### `src/gui/MainFrame.cpp`

主窗口实现。

主要工作：

- 创建菜单和工具栏；
- 创建左侧元件库列表；
- 创建中央 `FootprintCanvas`；
- 创建右侧封装属性和焊盘属性面板；
- 新建或打开封装；
- 保存当前封装；
- 刷新库列表；
- 把控件内容同步到 `currentFootprint_`；
- 显示错误和状态信息。

它调用两个下层服务：

```text
MainFrame
├─ IFootprintLibrary
│    └─ 读写 .fp
└─ IFootprintCodec
     └─ 对象和文本转换
```

当前骨架里的 `codec_` 成员已经被工厂创建，但直接的文件读写路径是交给 `IFootprintLibrary` 的。也就是说，Codec 的实际调用应该发生在 Library 的实现内部；`MainFrame` 不需要知道解析细节。

### `src/gui/FootprintCanvas.h`

画布类的声明。

它保存：

- 当前正在编辑的 `Footprint*`；
- 缩放比例和平移位置；
- 当前绘图工具；
- 当前鼠标选择；
- 拖动和临时绘制的状态。

它声明了画布绘制、鼠标事件、选择、拖动、栅格吸附等函数。

### `src/gui/FootprintCanvas.cpp`

画布实现，是 GUI 和两个服务之间的主要桥梁。

它负责：

- 把鼠标屏幕坐标转换为封装模型坐标；
- 调用 `IGeometryService::SnapToGrid`；
- 调用 `IGeometryService::HitTest`；
- 调用 `IFootprintEditor` 增加、移动、修改或删除图元；
- 绘制网格、焊盘、丝印、选择框和临时图形；
- 缩放、平移和发送变化通知。

比如放置 SMD 焊盘的实际流程是：

```text
鼠标按下
-> ScreenToModel
-> SnapToGrid
-> IFootprintEditor::AddSmdPad
-> Footprint.pads 增加对象
-> NotifyChanged
-> MainFrame 标记文档已修改
-> Refresh
```

这个文件不应该知道 `.fp` 文件的字段顺序。

## 4. src/todo：需要自己实现的四个文件

这四个文件是课程实验的核心工作量。

### `src/todo/FootprintEditorService.cpp`

对应接口：`IFootprintEditor`

需要实现：

1. 创建并添加 SMD 焊盘。
2. 创建并添加 THT 引脚。
3. 自动分配不重复的编号。
4. 添加线段、矩形、圆弧、多边形和文本。
5. 修改焊盘属性。
6. 平移焊盘。
7. 删除焊盘或任意丝印对象。

实现时要注意：

- 焊盘和丝印都直接追加到 `Footprint` 的对应 `vector`。
- `UpdatePad`、`MovePad`、`RemoveItem` 要先检查索引。
- 失败时返回 `false`，不能悄悄产生半修改状态。
- SMD 和 THT 使用不同的默认尺寸、形状和钻孔。
- 编号应该扫描现有焊盘，不能只依赖数组长度。

完成后可以独立验证：

```text
空 Footprint
-> AddSmdPad 两次
-> pads.size() == 2
-> number 分别为 1、2
```

### `src/todo/GeometryService.cpp`

对应接口：`IGeometryService`

需要实现：

1. 所有图元的边界框合并。
2. 焊盘的命中测试。
3. 线段的命中测试。
4. 矩形轮廓的命中测试。
5. 圆弧的命中测试。
6. 多边形边界的命中测试。
7. 文本的命中测试。
8. 栅格吸附。

重点是模型坐标和容差，不要写屏幕像素逻辑。调用方会把 `8 / zoom` 一类的模型空间容差传进来。

完成后可以独立验证：

```text
焊盘中心 (0, 0)
-> HitTest(0, 0, 容差)
-> 返回 Pad + index

空封装
-> ComputeBounds
-> 仍然返回有效范围，供 FitView 使用
```

### `src/todo/FootprintCodec.cpp`

对应接口：`IFootprintCodec`

需要实现：

1. 定义 `.fp` 文本格式。
2. 序列化封装的基本属性。
3. 序列化所有焊盘和丝印对象。
4. 反序列化文本。
5. 校验版本和字段。
6. 在错误时返回可显示的 UTF-8 错误字符串。

建议格式：

```text
EDALAB1_FOOTPRINT 1
NAME R_0805
CATEGORY Passive
DESC 0805 SMD land pattern
SILKCOLOR #1A6984
ORIGIN 0 0
PAD SMD ROUNDED 1 1 -0.9 0 1.3 1.5 0 0 0.1 0.2
LINE -0.5 -0.8 0.5 -0.8 0.12
END
```

这个文件只处理 `std::string` 和 `Footprint`，不要包含 `wxFile`、`wxFileDialog` 或 `wxWidgets` 控件。

完成后可以独立验证：

```text
构造一个含焊盘和丝印的 Footprint
-> Serialize
-> Deserialize
-> 名称、数量和关键坐标一致
```

### `src/todo/FilesystemFootprintLibrary.cpp`

对应接口：`IFootprintLibrary`

需要实现：

1. `DefaultDirectory` 返回稳定的 `footprints` 目录。
2. `Reload` 创建目录并扫描 `*.fp`。
3. `Read` 读取文件并调用 Codec 解析。
4. `Write` 序列化后写入文件。
5. `Delete` 安全删除封装文件。
6. 维护 `entries_`，供左侧库列表显示。

它应该依赖 `IFootprintCodec`，而不是自己解析每一行文本。

推荐目录策略：

```text
可执行文件目录/
└─ footprints/
   ├─ R_0805.fp
   ├─ HEADER2_1.fp
   └─ ...
```

这样从 Visual Studio、PowerShell 或桌面快捷方式启动时，不会因为当前工作目录不同而找不到库。

完成后可以独立验证：

```text
临时目录放两个 .fp
-> Reload
-> Entries().size() == 2
-> Read 一个文件得到 Footprint
-> Write 后再 Read，内容仍然正确
```

## 5. 构建和脚本文件

### `CMakeLists.txt`

CMake 项目入口。

负责：

- 查找 wxWidgets；
- 找到 `D:\wxWeigets\wxWidgets-3.3.3`；
- 指定静态库；
- 收集 GUI 和 TODO 的 `.cpp`；
- 生成 `EdaLab1Skeleton` 可执行文件；
- 设置 C++17；
- 设置 MSVC 的 `/utf-8`、`/W4` 等选项。

添加测试文件时，需要在这里增加测试目标并链接模型/逻辑源文件。

### `CMakePresets.json`

保存 CMake 预设：

```text
生成器：Ninja
构建类型：Release
wxWidgets 根目录：D:/wxWeigets/wxWidgets-3.3.3
构建目录：build-msvc
```

它适合 Visual Studio 或支持 CMake Presets 的编辑器使用。

### `build_msvc.ps1`

PowerShell 构建脚本。

它会：

1. 检查 wxWidgets 和 Visual C++ 环境是否存在；
2. 调用 `vcvars64.bat` 初始化 MSVC x64；
3. 调用 CMake 配置；
4. 调用 Ninja 编译。

平时直接执行：

```powershell
.\build_msvc.ps1
```

### `build-msvc/`

CMake 和 Ninja 自动生成的构建目录。

包含：

- `build.ninja`
- `CMakeCache.txt`
- `.obj`
- `.exe`
- CMake 内部文件

不要手动编辑这里的文件。需要重新构建时直接运行脚本或 CMake。

## 8. 文件之间的调用关系

把项目看成下面的链路：

```text
App.cpp
  -> MainFrame
       ├─ FootprintCanvas
       │    ├─ IGeometryService
       │    └─ IFootprintEditor
       │
       └─ IFootprintLibrary
            └─ IFootprintCodec
```

具体动作：

### 新建和绘制

```text
MainFrame 创建 currentFootprint_
-> FootprintCanvas::SetFootprint
-> 用户选择工具
-> 鼠标事件
-> GeometryService::SnapToGrid
-> FootprintEditorService::Add...
-> currentFootprint_ 改变
-> 画布刷新
```

### 选择

```text
FootprintCanvas 鼠标事件
-> GeometryService::HitTest
-> HitResult
-> MainFrame 刷新右侧属性
```

### 保存

```text
MainFrame::SaveCurrent
-> IFootprintLibrary::Write
-> IFootprintCodec::Serialize
-> 写入 footprints/*.fp
```

### 打开

```text
MainFrame::LoadSelectedLibraryEntry
-> IFootprintLibrary::Read
-> IFootprintCodec::Deserialize
-> Footprint
-> FootprintCanvas::SetFootprint
```

## 9. 修改顺序和边界

推荐按下面顺序修改：

1. `FootprintEditorService.cpp`
2. `GeometryService.cpp`
3. `FootprintCodec.cpp`
4. `FilesystemFootprintLibrary.cpp`
5. 增加 `tests/` 测试并修改 `CMakeLists.txt`

不建议：

- 在 `MainFrame.cpp` 里直接解析 `.fp`；
- 在 `FootprintCanvas.cpp` 里实现文件扫描；
- 在 `GeometryService.cpp` 里弹窗；
- 在 `FootprintTypes.h` 里放鼠标事件；
- 在 `src/todo/` 里包含 `wxWidgets` 控件并处理 UI。
